# 自动探测知名开源项目（按三层分类，star≥30k）

## 目标

按 **技术领域（6 大 TechDomain）/ 技术要素（=领域层 domain_code，开源域 tech_element）/ 技术方向（22 个 TechDirection）** 的分类体系，自动到 GitHub 搜索各方向下 star≥30k 的知名开源项目。探测结果**只预览不入库**——管理员勾选后才走现有"添加仓库"流程入库。

## 核心设计决策（已确认）

| 决策点 | 选择 |
|--------|------|
| 结果去向 | **只预览不入库**——结果暂存，管理员勾选后手动入库 |
| 交互模式 | **后台任务 + 进度条**（复用 lab prefetch 的 sys_config JSON 状态模式） |
| 搜索词来源 | **内置种子常量**（22 个方向各配 1-3 个英文搜索词，代码内维护） |
| star 阈值 | 默认 30000，面板可调 |
| 方向选择 | 面板勾选（默认全选 22 个） |

## 数据流

```
管理员在「自动探测」面板勾选方向 + 设阈值
   ↓ POST /open-source/discover/start（super_admin）
后台协程逐方向：
   search_repositories(q="topic:llm stars:>=30000", sort=stars)
   → 取 top N（每方向≤20，按 star 降序）
   → 逐仓调 get_repo 补语言/描述（search 结果已含，无需二次调用）
   → 去重（同仓命中多方向时合并，记录全部命中方向）
   → 结果 + 进度写入 sys_config（JSON）
   ↓
前端轮询 GET /open-source/discover/status
   ↓ 完成后
面板展示分组结果（按领域→方向分组，含 star/语言/描述/是否已在库）
   ↓ 管理员勾选
POST /open-source/discover/import（把勾选的仓库经现有 batch_create_repo_configs 入库）
```

## 后端改动（5 个文件）

### 1. GitHubClient 加 search 方法
**文件**：`backend/app/domains/open_source/services/github_client.py`

```python
async def search_repositories(self, query: str, sort: str = "stars",
                              order: str = "desc", per_page: int = 20) -> dict:
    """Search repositories. Returns {"items": [...], "total_count": N}."""
    return cast(dict, await self._get("/search/repositories",
        {"q": query, "sort": sort, "order": order, "per_page": per_page}))
```
- 走现有 `_get` 通道：token 轮换 / 429 重试 / X-RateLimit 头处理自动生效
- search API 限速 30 req/min（认证）——在探测 service 里用 `asyncio.sleep(2.5)` 简单节流即可（22 方向×~2 词≈50 次请求≈2 分钟，可接受）

### 3. 探测后台 Service
**文件**：`backend/app/domains/open_source/services/discover_service.py`（新建）

- `start_discovery(direction_codes: list[str], min_stars: int)`：查重（已有 running 任务则 409）→ `asyncio.create_task` 后台跑
- 后台协程 `run_discovery`（参照 lab `run_prefetch`）：
  - 状态键 `os_discover_status`（sys_config JSON）：`{status, processed, total, current, found, heartbeat_at, results}`
  - results 结构：`[{repo_full_name, display_name, description, language, stars, html_url, direction_codes: [...], domain_code, exists_in_config: bool}]`
  - 每方向：拼查询 → search_repositories → 过滤 star≥阈值、非 fork → 每 search 间隔 2.5s（search API 限速）
  - 跨方向去重：同 repo 命中多方向则合并 direction_codes
  - 最后批量查 `os_repo_config` 标记 `exists_in_config`（已入库的标记出，默认不勾选）
- `get_discovery_status()` → 返回状态+结果
- `import_discovered(selection: list[str], tech_element_by_domain)` → 复用 `batch_create_repo_configs`（tech_element 取该仓主命中方向的所属领域）

### 4. API 端点
**文件**：`backend/app/domains/open_source/api/collection.py`（或新文件 `discover.py`，建议新文件更清晰——`discover.py` 新建）

- `POST /open-source/discover/start` body `{direction_codes: [..], min_stars: int}`（super_admin）
- `GET /open-source/discover/status`（super_admin）→ 状态 + 分组结果
- `POST /open-source/discover/import` body `{repos: [{repo_full_name, tech_element}]}`（super_admin）
