# 启用行业人才库 API Key 导入 Push 通道

## 目标

启用预留的 `POST /api/v1/industry/import` 端点(当前返回 501),让 Agent/skill 在采集打分后,用 API Key 程序化调用导入数据,无需管理员手动上传。

## 核心设计决策(已确认)

| 决策点 | 选择 |
|--------|------|
| API Key 存储 | **数据库动态配置**(system_config 表,ConfigService 5 分钟 TTL 缓存,支持热改) |
| 请求格式 | **JSONL text + Query 参数**(raw body=JSONL,position_id/batch 走 query string) |
| 失败告警 | **日志 + 审计兜底**(logger.error + audit_log,暂不建 webhook) |
| 限流 | **先不做专用限流**(导入低频,走全局 RATE_LIMIT_ENABLED 开关) |
| API Key 配置项名 | `INDUSTRY_IMPORT_API_KEY`(对齐现有大写下划线命名) |

## 数据流

```
Agent/skill 采集打分 → scored.jsonl
   ↓
curl -X POST "https://server/api/v1/industry/import?position_id=5&batch=2026-08-llm" \
     -H "X-API-Key: <key>" \
     -H "Content-Type: application/x-jsonlines" \
     --data-binary @scored.jsonl
   ↓
verify_api_key 依赖校验 X-API-Key(对比 DB 里的 INDUSTRY_IMPORT_API_KEY)
   ↓
读取 raw body(JSONL text)+ 复用现有 IndustryImportService.import_jsonl
   ↓
审计日志(operation=import, user_id=None 标识机器调用) + 返回 IndustryImportReport
```

## 后端改动(6 个文件)

### 1. ConfigService:加 API Key 到脱敏清单
**文件**:`backend/app/domains/shared/services/config_service.py`

- `SENSITIVE_KEYS` 集合(L83)加 `"INDUSTRY_IMPORT_API_KEY"` —— 防止管理端 get_all 时明文泄露

### 2. 鉴权依赖:新增 verify_industry_api_key
**文件**:`backend/app/domains/industry/api/import_endpoint.py`(就近放,不污染 shared 的通用 auth_deps)

新增依赖函数 `verify_industry_api_key`:
- 参数:`api_key: str | None = Header(None, alias="X-API-Key")`、`session: AsyncSession = Depends(get_async_session)`
- 逻辑:
  1. 从 DB 读 `INDUSTRY_IMPORT_API_KEY`(`ConfigService(session).get_value("INDUSTRY_IMPORT_API_KEY", "")`)
  2. key 未配置(空) → 503 `{"detail": "Import API Key not configured"}`(提示管理员先配)
  3. 请求没带 X-API-Key 或不匹配 → 401
  4. 用 `secrets.compare_digest` 做常量时间比较(防时序攻击)
  5. 返回 `{"role": "import_agent", "source": "api_key"}` 标识机器调用方

### 3. 启用 push 端点(替换 501 占位)
**文件**:`backend/app/domains/industry/api/import_endpoint.py`

把 L62-78 的 501 占位改成真正实现:
```python
@router.post("/import", response_model=IndustryImportReport)
async def import_industry_talents_push(
    request: Request,
    position_id: int = Query(..., description="Target position for all rows"),
    batch: str | None = Query(None, description="Import batch identifier"),
    session: AsyncSession = Depends(get_async_session),
    _agent: dict = Depends(verify_industry_api_key),
) -> IndustryImportReport:
```
- **参数接收**:`position_id` / `batch` 走 Query;JSONL 走 raw body(`await request.body()` + UTF-8 解码 + 复用 `_MAX_UPLOAD_BYTES` 20MB 上限)
- **复用 importer**:同样调 `IndustryPositionService(session).get_position(position_id)` 校验岗位存在 → `IndustryImportService(session).import_jsonl(content, position_id, batch)`
- **审计**:
  - 成功:`AuditService.log_data_operation(user_id=None, operation="import", resource_type="industry_talent", status="success", detail={"source":"api_key","position_id":...,"batch":...,"rows":report.total_parsed})`
  - 失败:`logger.error(...)` + 同样审计 status=failure + error_message
- **更新 docstring**:去掉"reserved, not enabled",改为说明这是机器调用通道

### 4. 修 AuditService 的 event_subtype 硬编码瑕疵
**文件**:`backend/app/domains/shared/services/audit_service.py`

- `log_data_operation`(L123-151)加 `event_subtype: str = "export"` 参数(向后兼容默认值)
- 第 142 行 `event_subtype="export"` 改为 `event_subtype=event_subtype`
- 这样 import 审计能传 `event_subtype="import"`,查询审计日志时可区分导入/导出
- **影响面**:所有现有调用方(export 端点)不传这个参数 → 走默认值 `"export"` → 行为完全不变(向后兼容)

### 5. 测试
**文件**:`backend/tests/domains/industry/test_industry_push_import.py`(新建)

测试用例:
- `test_push_import_success` — 配置 API Key + 带正确 X-API-Key + JSONL body → 200,验证数据导入
- `test_push_import_missing_api_key_header` — 不带 X-API-Key → 401
- `test_push_import_wrong_api_key` — 错误 key → 401
- `test_push_import_api_key_not_configured` — DB 没配 key → 503
- `test_push_import_empty_body` — 空 body → 400(对齐 upload 的 aborted 语义)
- `test_push_import_unknown_position` — position_id 不存在 → 404
- `test_push_import_body_too_large` — 超 20MB → 400
- `test_push_import_audit_logged` — 验证审计日志写入了 operation=import
- `test_push_import_does_not_require_jwt` — 不带 Bearer token 只带 X-API-Key 也能通过(JWT 与 API Key 独立)

### 6. API Key 配置的种子入口
**文件**:`backend/app/domains/shared/api/system_config.py`(现有系统配置管理端)

这个端点已经能 CRUD system_config 表(12 处 ConfigService 调用)。管理员通过现有的「系统配置」界面:
- 新增配置:config_key=`INDUSTRY_IMPORT_API_KEY`,config_value=`<生成的强随机 key>`,is_sensitive=True
- 值会自动脱敏显示(因为加了 SENSITIVE_KEYS + is_sensitive=True)

**不写 seed 脚本** —— API Key 由管理员手动生成并配置(生成一个强随机串),不预置默认值(安全考虑:预置空值或弱默认值会误导)。

## 不做的事

- ❌ 不做专用限流(导入低频,走全局开关)
- ❌ 不建 webhook 告警服务(日志+审计兜底,后续可加)
- ❌ 不为 API Key 做专门配置 UI(复用通用系统配置 CRUD)
- ❌ 不改启动期安全校验(DB 配置运行期才查,启动校验管不到)
- ❌ 不改 JWT 鉴权体系(两套鉴权完全独立,挂在各自端点上)
