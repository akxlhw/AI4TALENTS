# V5.0.0 需求清单

## 1. 功能需求

### 1.1 数据导入

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|---------|
| F-IMP-01 | 管理员通过系统配置页上传 JSONL 文件导入行业人才 | P0 | 上传 scored JSONL → 解析 → upsert → 返回导入报告（新增/更新/跳过数） |
| F-IMP-02 | 导入时指定目标岗位 | P0 | 导入表单必选岗位（下拉）；导入的人才自动关联到该岗位 |
| F-IMP-03 | 人才全局去重（name + current_org） | P0 | 同一人才重复导入时更新基本信息，不重复创建 |
| F-IMP-04 | 关联表增量更新（保留状态） | P0 | 已有 touched/status/notes 的关联记录不被导入覆盖 |
| F-IMP-05 | 支持 skill API 推送导入（静态 API Key） | P1 | POST /api/v1/industry/import 带 API Key + position_id + JSONL body |

### 1.2 岗位管理

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|---------|
| F-POS-01 | 创建岗位（名称/部门/技术方向/职级范围/JD） | P0 | 系统配置页表单提交 → 创建成功 → 出现在岗位列表 |
| F-POS-02 | 编辑岗位 | P0 | 可修改所有字段；状态可切换 open/closed/archived |
| F-POS-03 | 删除岗位 | P1 | 删除岗位时关联记录一起删除（CASCADE） |
| F-POS-04 | 岗位列表查看 | P0 | 显示岗位名/候选人总数/平均匹配分/状态 |

### 1.3 人才浏览

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|---------|
| F-TAL-01 | 人才列表（卡片网格） | P0 | 展示姓名/现职/学历/匹配分/命中标签/命中岗位；分页 |
| F-TAL-02 | 多维度筛选 | P0 | 关键词/岗位/最低匹配分/状态/来源平台/技术方向 |
| F-TAL-03 | 排序 | P0 | 匹配分降序（默认）/姓名/最近导入 |
| F-TAL-04 | 人才详情页 | P0 | 基本信息 + 履历时间线 + 三维打分 + 多岗位匹配分对比 |
| F-TAL-05 | 候选人状态管理 | P1 | 详情页可修改某岗位下的 status/touched/notes |

### 1.4 导航

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|---------|
| F-NAV-01 | 主导航新增"行业人才"入口 | P0 | 与学术/开源/AI Native 并列，紫色域主题 |

## 2. 非功能需求

| 编号 | 需求 | 说明 |
|------|------|------|
| NF-01 | 跨域隔离 | `domains/industry/` 不 import 其他业务域内部模块；独立表（不复用 core_talent） |
| NF-02 | 架构合规 | 通过 check_architecture.py 三层检查（跨域/Endpoint/HTTP） |
| NF-03 | 迁移链 | 新迁移文件 down_revision 指向当前 head |
| NF-04 | 前端一致性 | 与其他域使用相同的组件库/状态管理模式/路由结构 |
| NF-05 | 导入性能 | 单文件 ≤20MB，解析 ≤5s，批量 INSERT 分批（≤500/批） |
| NF-06 | 安全 | 导入需鉴权（super_admin 或 API Key）；JSONL 解析失败不中断（逐行跳过） |

---

## 3. 约束

- **数据来源**：外部 skill 产出 JSONL（不主动采集）
- **打分**：由 skill 的 `rescore_v2.py` 完成，后端只存储
- **职级体系**：华为式数字序列（如 19-20 级），不建独立职级表
- **技术方向**：关联 `core_tech_direction`（需先填充种子数据）
