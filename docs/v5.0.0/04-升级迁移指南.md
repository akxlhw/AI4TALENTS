# V5.0.0 升级迁移指南（其他服务器）

> 适用：从 V4.x 升级到 V5.0.0（含技术分类体系 v2 迁移）
> 目标：避免分类体系变更导致的数据异常（venue 错绑、tech_element 遗留旧码、孤儿数据）

---

## 1. 升级前

```bash
# 1. 备份数据库（必须）
pg_dump -U talent_user talent_db > backup_pre_v5_$(date +%Y%m%d).sql

# 2. 记录升级前关键计数（用于升级后比对）
psql -U talent_user talent_db -c "
select 'core_tech_domain', count(*) from core_tech_domain
union all select 'config_venue', count(*) from config_venue
union all select 'venue_binding', count(*) from config_venue_tech_binding
union all select 'os_repo_config', count(*) from os_repo_config
union all select 'os_developer', count(*) from os_developer;"
```

## 2. 升级步骤（顺序不能乱）

```bash
# 1. 拉代码
git pull origin main

# 2. 后端依赖（V5.0.0 升级了 FastAPI 0.141 / starlette 1.6，必须重装）
cd backend && uv sync --all-groups

# 3. 数据库迁移（056~062 依次自动执行）
uv run alembic upgrade head
# 预期终点：062 (head)。062 会完成：
#   - core_tech_domain 从 6 个旧领域换成 10 个新领域
#   - 旧方向码按 OLD_DIRECTION_REMAP 重映射
#   - os_repo_config.tech_element 从旧领域码映射为要素码（JSON）
uv run alembic current   # 确认 = 062 (head)

# 4. 数据脚本（幂等，可重跑）
uv run python -X utf8 scripts/data/rebind_venues_v2.py    # 顶刊顶会按 v2 重绑 + 补新 venue
uv run python -X utf8 scripts/data/backfill_os_is_student.py  # 有开源数据时：回填在校生标签

# 5. 前端
cd ../frontend && npm ci && npm run build
```

## 3. 升级后校验（异常检测清单）

```bash
cd backend && uv run python -X utf8 -c "
import asyncio
from sqlalchemy.ext.asyncio import create_async_engine
from sqlalchemy import text
from app.core.config import settings

async def main():
    eng = create_async_engine(settings.DATABASE_URL)
    async with eng.connect() as c:
        # ① 领域数必须为 10，且每个领域都有 venue 绑定
        rows = (await c.execute(text('''
            select d.domain_code, count(b.binding_id)
            from core_tech_domain d
            left join config_venue_tech_binding b on b.tech_domain_id = d.tech_domain_id
            group by 1 order by 1'''))).all()
        print('venue bindings per domain:', rows)
        assert len(rows) == 10 and all(r[1] > 0 for r in rows), '有领域没有 venue 绑定!'

        # ② tech_element 不允许残留 v1 旧码
        bad = (await c.execute(text('''
            select repo_full_name, tech_element from os_repo_config
            where tech_element::text ~ '\"(ai|robotics|data_science|networks|systems|security)\"'
        '''))).all()
        print('legacy tech_element rows:', bad)
        assert not bad, '存在未迁移的旧领域码!'

        # ③ 孤儿检测：与已配置仓库零关联的开发者
        orphans = (await c.execute(text('''
            select count(*) from os_developer d
            where not exists (
              select 1 from os_contribution ct
              join os_repository r on r.repo_id = ct.repo_id
              join os_repo_config rc on rc.repo_full_name = r.full_name
              where ct.developer_id = d.developer_id)'''))).scalar()
        print('orphan developers:', orphans, '（有采集数据时应接近 0；未采集过的库为全量属正常）')
    await eng.dispose()

asyncio.run(main())
"
```

**判定规则**：
- ① 任何领域 venue 数为 0 → 漏跑 `rebind_venues_v2.py`
- ② 有输出 → 062 未成功执行，先 `alembic current` 确认版本再重跑
- ③ 孤儿数大且该库采集过数据 → 按「问题排查」第 2 条处理

## 4. 常见问题排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 领域列表不是 10 个 | 062 未执行 | `alembic upgrade head` 后重查 |
| 顶刊顶会配置页某领域为空 | 漏跑 rebind 脚本 | `uv run python -X utf8 scripts/data/rebind_venues_v2.py`（幂等可重跑） |
| 开源仓库技术领域显示英文码 | 前端缓存 | 强刷/清缓存；确认前端已重新 build |
| 开源开发者对不到项目 | 历史悬孤数据（purge 后残留的个人仓库关联） | 见 SUMMARY 或联系维护者按 os_* 表清理 |
| 迁移报某个 0xx 冲突 | 手动改过库结构 | `alembic stamp <上一版>` 后重跑 upgrade |

## 5. 回滚

```bash
# 应用层回滚
git checkout <旧版本 tag/commit> && cd backend && uv sync && uv run alembic downgrade <旧版编号>

# 数据层回滚（最可靠）
psql -U talent_user talent_db < backup_pre_v5_YYYYMMDD.sql
```

注意：062 的 downgrade 只能还原表结构，领域码的数据映射（旧方向→新方向）是单向的，**生产库务必先备份再升级**。
