# 31_MVP v1.1 变更需求清单（CR List）

**文档名称**：MVP v1.1 变更需求清单（CR List）  
**文档编号**：31  
**版本**：V1.0  
**状态**：冻结版  
**适用范围**：智能人才库—学术人才子系统 MVP v1.1

---

## 1. 变更背景

学术人才子系统在 `v1.0.0-mvp-baseline` 阶段已经完成基础可演示能力，能够支持首页总览、关键词搜索、按国家与学校浏览、学校信息页、人才列表页、人才详情页以及按学校范围的基础权限控制。  
在试用过程中，业务部门和国内/海外招聘平台进一步明确了系统使用诉求：业务部门更关注“自己的技术要素收录了多少人才、分布在哪些国家和学校”；平台部门更关注“自己负责的国家与院校区域收录了多少人才，覆盖了哪些技术要素”。同时，管理侧希望系统不只是静态浏览平台，而应具备可控的数据采集、周期配置、任务监控、版本发布和轻量纠偏能力。

基于以上背景，启动 `MVP v1.1` 版本。v1.1 相对于 v1.0 不是简单的界面改版，而是围绕**双主视角人才发现、轻量运营闭环、后台可控采集与发布**展开的一次明确的产品增强。

---

## 2. 变更原则

1. 在 `v1.0.0-mvp-baseline` 基线上增量迭代，不推翻已可演示主链路。  
2. 所有新增能力必须围绕“服务研发招聘”这一核心目标。  
3. 前台能力优先解决“看什么、怎么找、怎么继续跟进”三个问题。  
4. 后台能力优先解决“采什么、何时采、采后何时生效、如何控制风险”四个问题。  
5. 所有新增页面、热点标签、搜索结果、详情信息、导出和后台操作都必须统一受权限约束。  
6. 本清单一经确认，即作为 v1.1 范围冻结依据；后续新增需求需进入待评审池。

## 4. 详细变更说明

### CR-01 新增“技术要素”主视角
**背景**：业务部门无法直接从 v1.0 中看出“自己的业务方向覆盖了多少人才”。  
**设计要点**：
- 页面名称使用“技术要素”，不再使用“技术类目”
- 一级筛选为技术要素，二级筛选为技术方向
- 页面内通过 `国家分布 / 院校分布 / 人才明细` 三个 Tab 展示结果
- 页面既支持概要统计，也支持列表下钻和详情查看

**预期价值**：
- 帮助业务部门快速识别某技术要素的人才供给规模
- 降低从学校和搜索结果中“倒推技术方向”的认知成本

### CR-02 新增“国家院校”主视角
**背景**：平台部门更关心区域和国家院校覆盖，而不是直接看技术方向。  
**设计要点**：
- 页面名称使用“国家院校”，字段层仍拆为区域/国家/学校
- 页面内通过 `院校分布 / 技术要素分布 / 人才明细` 三个 Tab 展示结果
- 技术要素在本页为辅助分析维度，不是主轴

**预期价值**：
- 平台团队可以快速判断负责区域的重点国家和学校
- 反向识别该区域内主要支撑招聘的技术要素

### CR-03 / CR-04 首页新增双主视角概要区与热点标签
**背景**：首页必须同时照顾业务部门和平台部门，不能再只以学校总览为中心。  
**设计要点**：
- 首页保留全局基础统计和搜索入口
- 新增技术要素概要卡、国家院校概要卡
- 概要卡底部展示热点标签，支持带参跳转
- 热点标签按权限范围内人才数排序生成

**预期价值**：
- 首页从静态资源总览页升级为业务导向的统一入口页
- 减少用户进入系统后的“我应该点哪里”的犹豫

### CR-05 搜索增强
**背景**：v1.0 搜索不足以覆盖研发招聘场景下的组合查询。  
**设计要点**：
- 新增技术要素、技术方向、区域、国家、学校、角色、毕业状态、待确认状态等筛选
- 搜索结果仍保持教授偏卡片、学生偏表格的风格策略
- 搜索结果可直接发起收藏/入池/详情查看

### CR-06 / CR-07 人才详情增强与轻量运营
**背景**：v1.0 人才详情偏资料展示，缺少后续动作承接。  
**设计要点**：
- 详情页展示技术标签、招聘判断摘要、代表成果、完整度和待确认项
- 支持收藏、入池、备注、跟进状态
- 我的收藏页承担轻量运营收口

### CR-08 技术映射解耦
通过内部“技术要素 / 技术方向”与 OpenAlex 主题映射关系，避免业务层被外部主题体系绑死。

### CR-09 至 CR-12 后台采集与发布能力
构建“范围配置 → 策略配置 → 任务执行 → 候选版本 → 手动发布”的后台运营链路。

### CR-13 数据质量与纠偏
在版本级别展示关键质量摘要，并支持轻量人工修正。

### CR-14 权限扩展
从学校范围权限扩展到学校、国家、技术要素三维资源权限，并支持默认视角。

### CR-15 导出增强
支持在权限范围内导出关键结果并留痕。

## 6. 版本归属与边界

### 6.1 v1.1 必做
- 双主视角信息架构
- 首页双主视角概要
- 技术要素页
- 国家院校页
- 搜索增强
- 收藏 / 人才池 / 备注 / 跟进状态
- 采集范围与策略配置
- 采集任务与版本发布
- 权限扩展

### 6.2 v1.1 应做但可轻量
- 详情页招聘判断增强
- 数据质量摘要
- 轻量纠偏
- 导出留痕
- 默认视角

### 6.3 明确不纳入 v1.1
- ATS 深度集成
- 智能推荐与评分引擎
- 学院 / 实验室主链路
- 多数据源复杂融合
- 高复杂 BI 分析能力
- 自动消息提醒和告警

---

## 7. 冻结结论

本清单经确认后，作为学术人才子系统 `MVP v1.1` 的正式变更需求冻结依据。  
任何未列入本清单的新增能力，不得直接进入开发，应先进入待评审池，并判断其归属为：

- hotfix
- v1.1 增补
- v1.2 预留

本文件与 `32_MVP v1.1 范围边界与版本说明`、`06B_需求规格说明书` 一并构成 v1.1 范围控制的核心文档集。
