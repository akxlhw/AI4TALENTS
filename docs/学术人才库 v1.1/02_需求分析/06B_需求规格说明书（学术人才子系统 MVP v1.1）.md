# 06B_需求规格说明书（学术人才子系统 MVP v1.1）

**文档名称**：需求规格说明书（学术人才子系统 MVP v1.1）  
**文档编号**：06B  
**版本**：V1.0  
**状态**：冻结版  
**适用范围**：智能人才库—学术人才子系统 MVP v1.1

---

## 1. 文档概述

### 1.1 编制背景
学术人才子系统 MVP v1.0 已完成基础可演示能力，支持首页总览、关键字搜索、按国家与学校浏览、学校信息页、人才列表页、人才详情页与基础权限控制。  
在试用过程中，业务侧进一步明确：系统不应仅作为学校维度的资料库，而应转向服务研发业务招聘与区域招聘平台的实际工作场景，支持按技术要素和国家院校两个主要视角进行人才发现、分布观察与轻量运营。  
同时，管理侧提出需补齐后台数据采集范围配置、自动采集周期、任务运行监控、数据版本发布与基础数据质量校验能力。基于以上需求，形成 MVP v1.1 版本需求规格。

### 1.2 版本定义
MVP v1.1 的定义为：

> **从“学校维度的学术人才浏览库”升级为“面向研发招聘的技术要素与国家院校双视角人才发现与轻量运营平台”。**

### 1.3 文档适用对象
- 项目负责人
- 产品/方案设计人员
- Claude Code 协同开发执行者
- 前后端开发人员
- 测试与验收人员
- 业务试用与评审人员

## 2. 业务目标

### 2.1 总体目标
在 v1.0 基线可演示能力基础上，v1.1 重点补齐服务研发招聘业务的双视角发现能力、轻量运营能力与后台数据运营能力，使系统从静态浏览型资料库升级为可用于实际招聘支持的轻量平台。

### 2.2 分目标

#### 目标一：支持按技术要素发现人才
业务部门可按技术要素、技术方向快速评估人才供给，了解当前业务方向收录人才数量及其在国家和院校上的分布情况。

#### 目标二：支持按国家院校发现人才
国内/海外招聘平台可按区域、国家、学校快速评估人才供给，了解所负责区域中重点学校与主要技术要素覆盖情况。

#### 目标三：支持人才轻量运营
招聘使用者在发现人才后，可完成收藏、入池、备注、跟进状态管理等基础动作，形成最小跟进闭环。

#### 目标四：支持后台可控采集与发布
超级管理员可配置数据采集范围和自动采集周期，查看采集任务运行情况，控制数据版本发布，降低数据质量风险。

#### 目标五：支持多维权限约束
系统需将权限模型从学校范围扩展到国家范围和技术要素范围，确保首页、概览、搜索、详情、导出及后台操作统一受控。

## 4. 用户角色与使用场景

### 4.1 超级管理员
负责系统级配置与运维控制，主要关注：
- 数据采集范围配置
- 自动采集周期与采集策略
- 采集任务运行状态
- 数据版本生成与发布
- 技术要素映射维护
- 全局权限配置

### 4.2 业务管理员 / HR 管理员
负责业务运营与配置维护，主要关注：
- 用户权限维护
- 人才池管理
- 收藏与跟进管理
- 数据质量查看
- 关键字段人工纠偏

### 4.3 业务部门用户
负责从技术视角观察人才供给，主要关注：
- 本业务方向收录多少人才
- 分布在哪些国家
- 分布在哪些学校
- 哪些人才值得关注或跟进

### 4.4 国内 / 海外招聘平台用户
负责从区域视角观察人才供给，主要关注：
- 自己负责区域收录多少人才
- 覆盖了哪些重点学校
- 涉及哪些技术要素
- 哪些人才需要进一步查看

## 5. 术语定义

### 5.1 技术要素
技术要素是本系统中面向业务侧定义的一级技术分类名称，同时也是 v1.1 的一级页面名称之一。示例：AI、基础软件、硬件工程、可信安全、音视频多媒体。

### 5.2 技术方向
技术方向是技术要素下的二级细分方向，用于更精确地表达研究与招聘关注点。示例：多模态、数据库、编译器、嵌入式系统、流媒体编解码。

### 5.3 国家院校
国家院校是本系统中按区域 / 国家 / 学校维度进行观察与分析的页面名称，不对应单一字段，而是承载区域、国家、学校三个层级维度的页面体系。

### 5.4 收藏
用户对人才进行的轻量关注动作，用于后续快速回看和跟进。

### 5.5 人才池
用户或业务管理员按专题、方向、区域等方式归集人才的轻量运营容器。

### 5.6 数据版本
每次采集、处理并经管理员确认后生成的一次前台可用数据状态标识。

## 7. 功能需求

### 7.1 首页
首页作为统一入口页，用于承接全局概览、搜索主入口以及技术要素与国家院校两个主视角的概要统计和跳转入口。

首页应支持展示以下内容：
- 已收录高校数
- 教授类人才数
- 学生类人才数
- 总人才数
- 授权学校数
- 数据版本 / 更新时间

首页应新增主视角概要区，包括：
- 技术要素概要卡
- 国家院校概要卡

技术要素概要卡至少展示：
- 技术要素数
- 技术方向数
- 人才总数
- 覆盖国家数
- 覆盖院校数

国家院校概要卡至少展示：
- 覆盖国家数
- 覆盖院校数
- 人才总数
- 覆盖技术要素数

首页应轻量展示：
- 热门技术要素
- 重点国家
- 重点院校

首页所有统计和热点标签均必须基于当前用户可见权限范围计算。

### 7.2 技术要素
页面应支持按以下条件筛选：
- 技术要素
- 技术方向
- 关键词
- 国家
- 学校
- 人才角色
- 是否已毕业（可选）
- 待确认状态（可选）

页面应展示当前筛选结果下的概要指标：
- 人才总数
- 教授数
- 学生数
- 覆盖国家数
- 覆盖院校数

页面主视图应支持：
- 国家分布
- 院校分布
- 人才明细

### 7.3 国家院校
页面应支持按以下条件筛选：
- 区域
- 国家
- 学校
- 技术要素
- 技术方向
- 关键词
- 人才角色

页面应展示当前筛选结果下的概要指标：
- 人才总数
- 教授数
- 学生数
- 覆盖院校数
- 覆盖技术要素数

页面主视图应支持：
- 院校分布
- 技术要素分布
- 人才明细

### 7.4 人才搜索
搜索页应支持以下筛选条件：
- 关键词
- 技术要素
- 技术方向
- 区域
- 国家
- 学校
- 人才角色
- 是否已毕业
- 待确认状态

搜索结果应支持：
- 排序
- 清空筛选
- 切换视图
- 收藏
- 入池
- 查看详情

### 7.5 人才详情
详情页应至少展示：
- 姓名
- 当前角色
- 学校
- 国家
- 技术要素
- 技术方向
- 基础学术信息
- 近年代表成果摘要
- 数据完整度提示
- 待确认项

详情页应支持：
- 收藏
- 加入人才池
- 添加备注
- 设置跟进状态

### 7.6 我的收藏 / 人才池
系统应支持：
- 收藏人才
- 取消收藏
- 查看收藏列表
- 将人才加入人才池
- 查看人才池列表
- 添加备注
- 设置跟进状态

### 7.7 权限管理
系统应支持以下控制维度：
- 学校范围
- 国家范围
- 技术要素范围
- 默认视角

权限应统一作用于：首页统计、热点标签、技术要素页、国家院校页、搜索结果、人才详情、收藏与人才池、导出能力。

### 7.8 数据采集配置与任务管理
系统应支持：
- 采集范围配置：国家、学校、技术要素、技术方向
- 采集策略配置：手动、每日、每周、每两周、每月；全量 / 增量
- 任务管理：任务状态、开始时间、结束时间、成功 / 失败摘要、错误摘要
- 数据版本与发布：候选版本、当前生效版本、手动发布

### 7.9 数据质量与人工纠偏
系统应支持展示以下质量摘要：
- 学校归一成功数 / 待确认数
- 技术方向识别成功数 / 待确认数
- 角色识别成功数 / 待确认数

系统应支持以下轻量纠偏动作：
- 修正技术方向
- 修正角色
- 标记待确认
- 标记排除展示

### 7.10 导出
系统应支持导出：
- 搜索结果
- 技术要素结果
- 国家院校结果
- 收藏 / 人才池结果

导出结果仅限当前用户权限范围内的数据，并应记录导出人、导出时间、导出条件。

当前主数据底座仍基于 OpenAlex。系统业务模型需保持与数据源解耦，前台展示术语以内部定义为准，不直接暴露底层源结构。

### 8.2 数据建模要求
v1.1 需新增或扩展以下对象：

- 技术方向

- 人才方向标签
- 收藏
- 人才池
- 备注
- 跟进状态
- 采集范围
- 采集策略
- 采集任务
- 数据版本
- 发布记录

## 9. 非功能需求

### 9.1 可用性
页面应保持企业级 Web 风格，结构清晰，信息层级明确，避免过度视觉装饰。

### 9.2 可维护性
业务模型不得与单一外部数据源结构强耦合。新增页面与接口应尽量复用现有架构与规范。

### 9.3 安全性
所有页面、摘要、导出、详情和后台配置操作都必须纳入权限控制。权限校验以后端为最终边界。

### 9.4 可扩展性
v1.1 设计需为后续扩展以下方向预留空间：
- 开源生态人才子系统
- 行业 / 工业界人才子系统
- 竞赛人才子系统
- 校招博士人才库
- 人才地图 / 技术地图 / 合作地图对接

### 9.5 一致性
页面术语、字段命名、状态命名、接口返回风格应保持一致。“技术要素”作为页面名和一级分类名统一使用，不再使用“技术类目”。

---

## 10. 验收要求

验收时应重点确认：
- 首页是否形成双主视角入口与概要统计
- 技术要素页是否能支持业务部门观察人才分布
- 国家院校页是否能支持平台用户观察人才分布
- 搜索页是否支持双视角组合筛选
- 收藏 / 人才池 / 备注 / 跟进状态是否形成闭环
- 采集配置与发布链路是否可用
- 权限是否在新页面上正确生效

---

## 11. 需求冻结结论

本文件作为学术人才子系统 MVP v1.1 的需求规格冻结依据。后续方案设计、详细设计、前后端开发、测试用例编制与验收口径均应以本文件为基准。凡不在本文件范围内的新增内容，须先进入变更评审，不得直接纳入 v1.1 开发。
