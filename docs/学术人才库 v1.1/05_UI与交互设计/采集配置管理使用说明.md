# 采集配置管理使用说明

**文档版本**: V1.1
**更新日期**: 2024-03-24

---

## 1. 功能概述

采集配置管理用于配置和管理从 OpenAlex 学术数据库采集学者、论文、机构数据的任务。

### 简化设计理念

MVP v1.1 采用简化设计，核心逻辑：**技术要素 → 顶会顶刊 → 采集任务**

| 参数类型 | 参数 | 配置方式 |
|---------|------|---------|
| 固定参数 | 数据类型 | 学者、论文、机构（固定） |
| 固定参数 | 时间范围 | 2010.1.1 至今（固定） |
| 可配置参数 | 采集范围 | 技术要素关联的顶会顶刊 |
| 可配置参数 | 采集模式 | 全量/增量 |

---

## 2. 页面结构

页面包含两个Tab：
1. **技术要素配置** - 管理技术要素关联的顶会顶刊
2. **采集任务** - 查看和管理采集任务

---

## 3. 操作步骤

### 3.1 配置顶会顶刊

1. 进入「采集配置管理」页面，默认显示「技术要素配置」Tab
2. 在技术要素列表中找到需要配置的要素
3. 点击「配置」按钮
4. 在弹窗中输入顶会顶刊列表（每行一个）
5. 格式：`ID|名称|类型`（类型可选：conference/journal）

**示例：**
```
NeurIPS|Neural Information Processing Systems|conference
ICML|International Conference on Machine Learning|conference
JMLR|Journal of Machine Learning Research|journal
```

6. 点击确定保存配置

### 3.2 启动采集

1. 确保技术要素已配置顶会顶刊
2. 点击「采集」按钮
3. 在确认弹窗中选择采集模式：
   - **全量采集**：采集所有符合条件的数据
   - **增量采集**：仅采集新增/更新的数据
4. 点击「确认采集」启动任务
5. 任务将**后台异步执行**，可切换到「采集任务」Tab 查看进度

### 3.3 查看任务进度

1. 切换到「采集任务」Tab
2. 查看任务列表，包含：
   - 任务编码
   - 技术要素
   - 采集模式
   - 状态（待执行/执行中/已完成/失败/已取消）
   - 进度百分比
   - 当前步骤
   - 记录数
   - 触发时间
3. 任务执行过程中：
   - 进度会实时更新
   - 当前步骤显示正在采集的顶会顶刊名称
4. 点击查看图标查看任务详情

### 3.4 取消任务

仅待执行和执行中的任务可以取消：
1. 在任务列表中找到目标任务
2. 点击取消按钮
3. 确认取消

## 4. 后台采集执行器

### 架构说明

```
用户请求 → API Endpoint → 创建任务记录 → 启动后台任务
                                         ↓
                              CollectService.execute_task()
                                         ↓
                              遍历顶会顶刊 → 调用 OpenAlex API
                                         ↓
                              解析数据 → 入库 → 更新进度
```

### 关键组件

| 组件 | 文件 | 说明 |
|------|------|------|
| 采集服务 | `app/services/collect_service.py` | 核心采集逻辑 |
| API 端点 | `app/api/v1/endpoints/collect.py` | 接口定义和后台任务调度 |
| 数据模型 | `app/models/sync.py` | 任务数据结构 |
| 仓库层 | `app/repositories/collect_repository.py` | 数据访问 |

### 采集流程

1. **初始化**
   - 获取技术要素配置
   - 验证采集源

2. **遍历采集源**
   - 对每个顶会顶刊调用 OpenAlex API
   - 获取在该顶会顶刊发表过论文的学者

3. **数据解析**
   - 判断学者角色（教授/学生/已毕业）
   - 提取研究方向
   - 匹配或创建学校记录

4. **入库保存**
   - 检查是否已存在（去重）
   - 创建新的学者记录

5. **进度更新**
   - 实时更新进度百分比
   - 更新当前步骤描述

### 角色判断逻辑

| 条件 | 角色类型 | 置信度 |
|------|---------|--------|
| works_count >= 50 且 h_index >= 20 | 教授 | 95% |
| works_count >= 30 且 cited_by >= 1000 | 教授 | 90% |
| works_count >= 20 且 h_index >= 10 | 教授 | 85% |
| works_count <= 8 | 学生 | 80% |
| works_count <= 15 且 cited_by < 200 | 学生 | 75% |
| 8 < works_count < 20 | 已毕业 | 70% |
| 其他 | 教授 | 60% |

## 6. 日志与问题定位

### 日志位置

后端日志通过 Python logging 模块输出，可通过以下方式查看：

```bash
# 查看 uvicorn 日志
cd backend
python -m uvicorn app.main:app --port 8003 --log-level info
```

### 关键日志信息

```
INFO: Created collect task 123 for 人工智能
INFO: Starting collect task 123 for 人工智能, 13 venues
INFO:   NeurIPS: fetched 150 authors, saved 120
INFO:   ICML: fetched 180 authors, saved 145
INFO: Collect task 123 completed: 800 authors saved
```

### 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| 任务一直 pending | 后台任务未启动 | 检查 uvicorn 日志 |
| 进度始终为 0 | OpenAlex API 超时 | 检查网络连接，稍后重试 |
| 记录数为 0 | 顶会顶刊配置错误 | 检查 venue ID 是否正确 |
| 任务失败 | 网络错误/API限流 | 查看错误信息，稍后重试 |

## 7. 注意事项

1. **并发限制**：同一技术要素同时只能有一个执行中的任务

2. **采集时间**：全量采集耗时较长（每个顶会顶刊约1-2分钟），建议在业务低峰期执行

3. **API 限流**：OpenAlex API 有请求频率限制，系统已内置请求间隔避免触发限流

4. **数据去重**：系统会自动跳过已存在的学者记录（基于 OpenAlex ID）

## 8. API 参考

### 获取技术要素配置列表
```
GET /api/v1/collect/tech-elements
```

### 更新技术要素的采集源
```
PUT /api/v1/collect/tech-elements/{id}/sources
Body: { "collect_sources": [...] }
```

### 触发采集任务
```
POST /api/v1/collect/tasks
Body: { "tech_element_id": 1, "collect_mode": "full" }
```

### 获取任务列表
```
GET /api/v1/collect/tasks?status=running&page=1&page_size=20
```

### 获取任务详情
```
GET /api/v1/collect/tasks/{id}
```

### 取消任务
```
POST /api/v1/collect/tasks/{id}/cancel
```
