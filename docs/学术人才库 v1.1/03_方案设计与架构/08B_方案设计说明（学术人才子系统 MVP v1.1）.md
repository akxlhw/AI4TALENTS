# 08B_方案设计说明（学术人才子系统 MVP v1.1）

**文档名称**：方案设计说明（学术人才子系统 MVP v1.1）  
**文档编号**：08B  
**版本**：V1.0  
**状态**：冻结版  
**适用范围**：智能人才库—学术人才子系统 MVP v1.1

---

## 1. 文档概述

### 1.1 编制背景
v1.1 不是对 v1.0 的简单修补，而是在既有基线之上，围绕“服务研发招聘”的目标进行系统增强。为避免在实施时出现页面表达不清、模块职责混乱、后台能力碎片化等问题，需要以方案文档明确整体设计思路、信息架构、应用架构和数据运营机制。

### 1.2 方案目标
- 建立“技术要素”和“国家院校”两个主视角
- 让首页成为统一入口和概要看板
- 在前台实现轻量运营闭环
- 在后台形成可控的数据采集和版本发布机制
- 保持与 OpenAlex 的业务层解耦
- 让权限模型扩展到多维资源范围

---

## 2. 方案设计原则

1. **基线继承**：在 v1.0.0-mvp-baseline 上增量升级，不做推翻式重构。  
2. **双视角并行**：技术要素和国家院校是并行主视角，不相互替代。  
3. **首页轻入口**：首页只承担概览、搜索和双主视角入口，不承担重分析。  
4. **数据源解耦**：业务模型与 OpenAlex 主题结构分离。  
5. **后台可控**：采集、任务、版本、发布要形成受控链路。  
6. **统一权限**：首页、热点标签、搜索、详情、导出和后台操作均统一受控。  
7. **可扩展**：为后续更多人才子系统预留结构空间。

## 3. 信息架构方案

### 3.1 一级导航
- 首页
- 技术要素
- 国家院校
- 人才搜索
- 我的收藏
- 权限管理

### 3.2 页面职责

#### 首页
展示全局基础统计，提供搜索入口和双主视角概要卡，并通过热点标签引导用户进入后续分析链路。

#### 技术要素
以“技术要素 / 技术方向”为主维度，查看国家分布、院校分布和人才明细。

#### 国家院校
以“区域 / 国家 / 学校”为主维度，查看院校分布、技术要素分布和人才明细。

#### 人才搜索
作为横向统一检索页，支持多条件组合筛选。

#### 我的收藏
承接收藏、人才池、备注和跟进状态，形成轻量运营闭环。

#### 权限管理
维护页面权限、资源范围权限和默认视角。

### 3.3 两条主分析链路
- 首页 → 技术要素 → 国家/院校分布 → 人才明细 → 详情 → 运营动作
- 首页 → 国家院校 → 院校/技术要素分布 → 人才明细 → 详情 → 运营动作

---

## 4. 业务架构方案

### 4.1 业务对象分层

#### 基础对象
区域、国家、学校、人才、角色。

#### 分析对象
技术要素、技术方向、技术方向映射、人才技术标签。

#### 运营对象
收藏、人才池、备注、跟进状态。

#### 数据运营对象
采集范围、采集策略、采集任务、数据版本、发布记录、数据质量摘要、纠偏记录。

### 4.2 双主视角业务模型

#### 技术要素视角
技术要素 → 技术方向 → 国家 / 学校 / 人才

#### 国家院校视角
区域 → 国家 → 学校 → 技术要素 / 人才

两个视角共享同一人才底座，只是聚合和展示维度不同。

## 6. 前台方案设计

### 6.1 首页方案
首页使用“基础统计 + 搜索 + 主视角概要区”的结构。  
主视角概要区由技术要素概要卡和国家院校概要卡组成，并通过热点标签提供快速入口。

### 6.2 技术要素方案
技术要素页采用“筛选区 + 概要统计 + Tabs 主视图”结构。  
Tabs 为：
- 国家分布
- 院校分布
- 人才明细

### 6.3 国家院校方案
国家院校页采用平行结构。  
Tabs 为：
- 院校分布
- 技术要素分布
- 人才明细

### 6.4 搜索方案
搜索页承接跨视角组合查询，但不替代双主视角业务看板。

### 6.5 详情与运营方案
详情页重点提供招聘判断信息；收藏、人才池、备注和跟进状态承接轻量运营闭环。

---

## 7. 后台方案设计

### 7.1 采集范围配置方案
采用白名单启用制，按国家、学校、技术要素、技术方向维护范围。

### 7.2 采集策略配置方案
采用固定选项调度策略，不使用复杂 Cron 表达式，支持：
- 手动
- 每日
- 每周
- 每两周
- 每月
- 全量
- 增量

### 7.3 任务管理方案
每次任务保存完整执行记录，包括编号、状态、摘要和错误信息。

### 7.4 版本与发布方案
采用“候选版本 → 手动发布 → 当前生效版本”的机制。  
前台只读取当前生效版本，避免未校验数据直接上屏。

### 7.5 数据质量与纠偏方案
提供基础质量摘要和轻量人工纠偏，不做复杂规则引擎。

---

## 8. 数据架构方案

### 8.1 数据层次
- 源数据层
- 标准化层
- 业务对象层
- 展示与统计层

### 8.2 技术映射方案
通过“技术要素 → 技术方向 → OpenAlex 主题映射”的三层方式实现业务层和源数据层解耦。

### 8.3 统计口径方案
首页、技术要素页、国家院校页和搜索页均必须基于：
- 当前生效版本
- 当前用户权限范围
- 当前筛选条件

---

## 9. 权限架构方案

### 9.1 权限组成
- 角色权限
- 学校范围权限
- 国家范围权限
- 技术要素范围权限
- 默认视角

### 9.2 权限作用点
必须作用于：首页统计、热点标签、列表结果、详情页、导出和后台高危操作。

### 9.3 核心约束
- 后端是最终权限边界
- 首页统计必须先裁剪后统计
- 默认视角不绕过权限校验

---

## 10. 关键流程方案

### 10.1 用户进入流程
登录后根据默认视角进入首页或对应主页面；页面加载摘要、筛选项和列表，再由用户进入后续分析链路。

### 10.2 数据运营流程
范围/策略配置 → 任务执行 → 候选版本 → 质量摘要 → 手动发布 → 前台生效。

---

## 11. 风险与控制策略

- **首页过重**：首页只做概览与入口，不做重分析。  
- **技术映射不准**：先规则映射 + 人工纠偏。  
- **权限口径不一致**：后端统一权限边界。  
- **未校验数据误发布**：引入候选版本和手动发布。  
- **范围持续膨胀**：用 31 和 32 文档冻结范围。
