## 📋 概述

### 设计背景
智能人才库第一阶段以OpenAlex作为学术人才的主要数据来源。为保证数据质量、同步效率和系统稳定性，需要设计清晰的数据管道（Data Pipeline），涵盖数据采集、清洗转换、质量校验和入库发布全流程。

### 设计原则
1. **解耦原则**：采集层与业务层解耦，避免OpenAlex数据结构直接污染业务模型
2. **幂等性原则**：同步任务支持重跑，结果保持一致
3. **可追溯原则**：每个数据对象都能追溯到来源批次和原始数据
4. **质量优先原则**：数据质量有问题时宁缺毋滥，标记为待确认
5. **渐进完善原则**：先跑通主干流程，再逐步优化细节

### 技术栈参考
- **数据源**：OpenAlex REST API
- **编程语言**：Python 3.11
- **数据库**：PostgreSQL 14+
- **任务调度**：初期使用脚本 + Cron，后期可升级为Celery
- **监控**：Prometheus + Grafana（可选）

### 3. 错误处理与重试

#### 3.1 重试策略
```python
# 指数退避重试装饰器
def exponential_backoff_retry(max_retries=3, base_delay=1):
    def decorator(func):
        def wrapper(*args, **kwargs):
            for attempt in range(max_retries):
                try:
                    return func(*args, **kwargs)
                except (RequestException, Timeout) as e:
                    if attempt == max_retries - 1:
                        raise
                    delay = base_delay * (2 ** attempt) + random.uniform(0, 0.1)
                    time.sleep(delay)
            return None
        return wrapper
    return decorator

@exponential_backoff_retry(max_retries=3, base_delay=1)
def fetch_openalex_data(endpoint, params):
    response = requests.get(endpoint, params=params, timeout=30)
    response.raise_for_status()
    return response.json()
```

#### 3.2 错误分类处理
| 错误类型 | 处理策略 | 记录方式 |
|----------|----------|----------|
| **网络超时** | 指数退避重试 | 记录到sync_batch.error_message |
| **API限流** | 等待后重试 | 记录限流响应头信息 |
| **数据格式错误** | 跳过当前记录，继续后续 | 记录到raw_source_record.error_info |
| **认证失败** | 立即停止，人工介入 | 发送告警通知 |

```python
def standardize_institution_name(name):
    """
    标准化机构名称
    示例: "Massachusetts Institute of Technology (MIT)" → "MIT"
    """
    # 1. 去除括号内容（保留常见缩写）
    patterns = [
        (r"\((MIT|Stanford|Harvard|Cambridge|Oxford)\)", r"\1"),  # 保留知名缩写
        (r"\([^)]*\)", ""),  # 去除其他括号内容
    ]

    for pattern, replacement in patterns:
        name = re.sub(pattern, replacement, name)

    # 2. 标准化大学名称
    name_mapping = {
        "Massachusetts Institute of Technology": "MIT",
        "Stanford University": "Stanford",
        "Harvard University": "Harvard",
        "University of Cambridge": "Cambridge",
        "University of Oxford": "Oxford",
        # ... 更多映射
    }

    return name_mapping.get(name.strip(), name.strip())
```

```python
def identify_role_type(author_data):
    """
    识别作者角色类型
    返回: 'professor', 'student', 'graduate', 'unknown'
    """
    # 规则1：基于机构类型判断
    institution_type = author_data.get("last_known_institution", {}).get("type")
    if institution_type == "education":
        # 规则2：基于作者统计信息判断
        works_count = author_data.get("works_count", 0)
        cited_by_count = author_data.get("cited_by_count", 0)

        if works_count > 20 and cited_by_count > 100:
            return "professor"
        elif works_count < 10:
            return "student"
        else:
            return "graduate"

    return "unknown"
```

```python
def extract_research_areas(concepts):
    """
    从OpenAlex概念中提取研究方向
    """
    if not concepts:
        return []

    # 按分数排序，取前5个
    sorted_concepts = sorted(concepts, key=lambda x: x.get("score", 0), reverse=True)
    top_concepts = sorted_concepts[:5]

    return [
        {
            "concept_id": c.get("id", "").split("/")[-1],
            "concept_name": c.get("display_name", ""),
            "score": c.get("score", 0),
            "level": c.get("level", 0)
        }
        for c in top_concepts
    ]
```

### 3. 质量校验规则

#### 3.1 数据质量维度
| 质量维度 | 校验规则 | 处理方式 |
|----------|----------|----------|
| **完整性** | 关键字段（姓名、机构）非空 | 标记为"needs_review" |
| **准确性** | 机构名称能匹配到已知学校 | 使用机构别名表匹配 |
| **一致性** | 同一作者信息在不同来源一致 | 合并冲突，人工复核 |
| **时效性** | 数据更新时间在3年内 | 标记陈旧数据 |

#### 3.2 质量评分模型
```python
def calculate_data_quality_score(cleaned_data):
    """
    计算数据质量分数（0-100）
    """
    score = 100

    # 扣分规则
    if not cleaned_data.get("name"):
        score -= 30  # 缺少姓名

    if not cleaned_data.get("last_known_institution"):
        score -= 20  # 缺少机构

    if cleaned_data.get("works_count", 0) == 0:
        score -= 10  # 无成果记录

    if cleaned_data.get("role_type") == "unknown":
        score -= 15  # 角色未知

    # 加分规则
    if cleaned_data.get("orcid"):
        score += 10  # 有ORCID标识

    if cleaned_data.get("research_areas"):
        score += 5   # 有研究方向

    return max(0, min(100, score))
```

#### 3.3 质量异常处理
```python
def handle_quality_issues(cleaned_data):
    """
    处理数据质量问题
    """
    issues = []

    # 检查并记录问题
    if cleaned_data["quality_score"] < 60:
        issues.append("low_quality_score")

    if cleaned_data["role_confidence"] < 0.7:
        issues.append("low_role_confidence")

    if not cleaned_data.get("research_areas"):
        issues.append("no_research_areas")

    # 根据问题严重程度标记状态
    if "low_quality_score" in issues:
        cleaned_data["clean_status"] = "needs_review"
    elif issues:
        cleaned_data["clean_status"] = "needs_enhancement"

    cleaned_data["quality_issues"] = issues
    return cleaned_data
```

```python
    """
    解决学校冲突
    """
    conflict_type = detect_conflict_type(existing_school, new_school_data)

    if conflict_type == "name_variant":
        # 名称变体，添加到别名表
        add_school_alias(existing_school["school_id"], new_school_data["name"])
        return existing_school["school_id"]

        create_review_task(existing_school, new_school_data)
        return None  # 暂不合并

        # 明确重复，自动合并
        merged_school = merge_school_data(existing_school, new_school_data)
        update_school(merged_school)
        return existing_school["school_id"]

    return None
```

```python
def deduplicate_authors(author_list):
    """
    作者去重逻辑
    """
    # 去重维度
    dedupe_keys = []

    for author in author_list:
        # 基于ORCID去重（最准确）
        if author.get("orcid"):
            key = f"orcid:{author['orcid']}"

        # 基于姓名+机构去重
        elif author.get("name") and author.get("last_known_institution"):
            inst_id = extract_institution_id(author["last_known_institution"])
            key = f"name_inst:{author['name']}:{inst_id}"

        # 基于OpenAlex ID去重
        else:
            key = f"openalex:{author['openalex_id']}"

        dedupe_keys.append(key)

    # 按去重键分组
    unique_authors = {}
    for i, key in enumerate(dedupe_keys):
        if key not in unique_authors:
            unique_authors[key] = author_list[i]
        else:
            # 合并重复作者
            unique_authors[key] = merge_author_data(unique_authors[key], author_list[i])

    return list(unique_authors.values())
```

```python
def build_search_text(talent_data, school_data):
    """
    构建全文搜索文本
    """
    parts = [
        talent_data.get("name", ""),
        school_data.get("name", ""),
        " ".join([area["concept_name"] for area in talent_data.get("research_areas", [])]),
        talent_data.get("orcid", ""),
    ]
    return " ".join(filter(None, parts))
```

1. **批量处理**：使用批量插入代替逐条插入
2. **并行处理**：不同类型数据并行清洗
3. **内存管理**：分批处理大数据集，避免内存溢出
4. **索引优化**：为查询频繁的字段建立索引

### 3. 错误监控与告警

#### 3.1 错误分类
| 错误级别 | 错误类型 | 处理方式 |
|----------|----------|----------|
| **P0-紧急** | 数据源不可用、数据库连接失败 | 立即通知，人工介入 |
| **P1-高** | API限流、大批量数据错误 | 自动重试，记录告警 |
| **P2-中** | 单条数据解析失败、网络波动 | 跳过错误，继续执行 |
| **P3-低** | 数据质量警告、非关键字段缺失 | 记录日志，定期回顾 |

#### 3.2 告警规则示例
```yaml
# Prometheus告警规则
groups:

    rules:
      - alert: DataSyncFailed
        expr: talent_sync_batch_failed_total > 0

          severity: P1
        annotations:
          summary: "数据同步任务失败"
          description: "批次 {{ $labels.batch_id }} 同步失败，错误: {{ $labels.error }}"

      - alert: DataQualityLow
        expr: talent_data_quality_score < 60
        for: 1h
        labels:
          severity: P2
        annotations:
          summary: "数据质量过低"
          description: "批次 {{ $labels.batch_id }} 数据质量分数低于60分"
```

### 3. 故障处理指南

#### 3.1 常见问题处理
| 问题现象 | 可能原因 | 解决步骤 |
|----------|----------|----------|
| **API调用频繁失败** | OpenAlex限流或网络问题 | 1. 检查网络连接<br>2. 降低请求频率<br>3. 检查API密钥配额 |
| **数据库插入慢** | 索引缺失或锁冲突 | 1. 检查数据库性能<br>2. 优化批量插入<br>3. 调整并发数 |
| **内存使用过高** | 单批次数据量太大 | 1. 减小batch_size<br>2. 分批处理<br>3. 优化数据清理 |
| **数据质量下降** | 清洗规则不匹配新数据 | 1. 检查清洗日志<br>2. 更新清洗规则<br>3. 人工复核样本 |

#### 3.2 应急恢复流程
```
故障发生 → 停止当前任务 → 分析错误日志 → 确定影响范围
    ↓
人工介入处理 → 修复问题 → 验证修复 → 重新执行/继续
    ↓
更新文档 → 复盘改进
```
