# 03 导入接口与标准

> 竞赛人才域 v1.0 —— 导入端点、校验、去重、替换策略、事务与幂等、错误报告

## 1. 导入方式

M1 仅保留**管理员手动上传**一种方式（与 lab 域 V3.0 收敛后的结论一致）：

```
POST /api/v1/comp/import
Content-Type: multipart/form-data（字段名 file，.jsonl，≤ 20MB）
鉴权：require_super_admin
响应：200 CompImportReport / 400（schema 不兼容、文件结构错误）/ 413（超限）
```

- 同步执行（单赛事文件 ≤ 数万行，秒级完成；M1 不引入后台任务）
- 服务端不做格式猜测：只接受 [02 文档 §3](02_数据源与爬虫Schema.md) 定义的 `schema_version: "1.0"` 文件

## 2. 导入流水线（CompImportService.import_jsonl）

```
parse（逐行校验） → guard（空/全无效拒收） → 单事务：
  upsert series → upsert contest →
  DELETE 旧 results（个人+团队） → 逐 team 行：
    upsert team（画像合并非空值） → INSERT 团队 result
  → 逐 person 行：
    upsert talent（画像合并非空值） → INSERT 个人 result（有 team_name 时关联 team_id）
  → 重算本场涉及选手/队伍的聚合字段
→ commit → 返回 CompImportReport
```

### 2.1 解析与校验（逐行，带行号）

| 规则 | 失败处理 |
|------|---------|
| 非合法 JSON | 记 `skip_reason(line, "invalid JSON")` 继续 |
| 行序违反 meta→series→contest→person | **整单拒收**（400，结构错误） |
| meta.schema_version ≠ "1.0" | **整单拒收**（400，不兼容版本） |
| meta.series/contest 行缺失或不唯一 | **整单拒收**（400） |
| meta.source_code ≠ series.code，或 meta.contest_external_id ≠ contest.external_id | **整单拒收**（400，文件内不一致） |
| person 缺 `handle` 或 handle 空白 | 记 skip（`missing handle`）继续 |
| person.result 缺失且 rank 与 participated 均无 | 记 skip（`missing result`）继续 |
| team 缺 `name` 或 name 空白 | 记 skip（`missing team name`）继续 |
| team.result 缺失 | 记 skip（`missing team result`）继续 |
| person.team_name 存在但文件中无对应 team 行 | 记 warning 并**自动补建 team 行**（仅有 name），不拒收 |
| result.award ∉ {gold,silver,bronze,hm,none} | 记 skip（`invalid award`）继续 |
| 未知 type 行 | 记 skip（`unknown type: X`）继续 |

### 2.2 空文件守卫（继承 lab 教训，硬性规则）

> **若 `parsed` 为空（0 条有效 person）且原文件存在非空行 → 拒绝导入，返回错误报告，数据库零改动。**
> 空 parsed 绝不允许触发 DELETE。这条是 V3.1.0 lab 域事故修复的同款守卫，直接内建。

### 2.3 去重键

| 实体 | 键 | 行为 |
|------|----|------|
| series | `code` | upsert：存在则更新画像字段（非空才覆盖） |
| contest | `(source_code, external_id)` | upsert：更新 name/start_time/status/raw_meta |
| talent | `(source_code, lower(handle))` → `dedup_hash` | upsert：画像字段**非空才覆盖**（school/country/avatar/profile/rank_title）；`real_name` 同理；`max_rating` 取两者较大值 |
| team | `(source_code, lower(name), school)` → `dedup_hash` | upsert：画像字段非空才覆盖 |
| result（个人） | `(talent_id, contest_id)` | 由"先删后插"保证，不会撞唯一键 |
| result（团队） | `(team_id, contest_id)` | 同上 |

**批内去重**：同一文件内重复 handle → 保留最后一条；重复 team（同 name+school）→ 合并 members、保留最后一条 result（与 lab 批内 dedup 一致，防唯一键冲突）。

### 2.4 替换策略（原子单位 = 一场赛事）

```python
async with session.begin():  # 单事务
    series = await upsert_series(line_series)
    contest = await upsert_contest(series, line_contest)
    deleted = await repo.delete_results_by_contest(contest.contest_id)  # 个人+团队全清
    for team_row in deduped_teams:
        team = await upsert_team(team_row)
        await repo.insert_result(contest.contest_id, team_row.result, team_id=team.team_id)
    for row in deduped_persons:
        talent = await upsert_talent(row)
        team_id = team_ids.get(row.team_name.lower()) if row.team_name else None
        await repo.insert_result(talent.talent_id, contest.contest_id, row.result, team_id=team_id)
    await recompute_aggregates(involved_talent_ids)
```

- **单事务**：delete + insert + 聚合重算同生共死，失败整体回滚（lab 已验证的模式）
- **幂等**：同一文件重复导入结果完全相同（delete 后重建）
- **并发**：同一 (source, contest) 的导入加进程内锁（`asyncio.Lock` per key），防两个管理员同时传同一场

### 2.5 聚合重算（import 内同步完成）

对本次涉及的 talent_id 集合：

| 字段 | 规则 |
|------|------|
| `current_rating` | 优先 person.rating（文件画像值）；否则取该选手最新一场（按 contest.start_time）的 rating_after |
| `max_rating` | max(原值, 文件 max_rating, 各场 rating_after) |
| `contests_count` | `count(results)`（全库重算，不限本文件） |
| `medals_*` | 按全库 `result.award` 重新计数 |
| `last_contest_at` | 最新一场 contest.start_time |
| `rank_title` | 文件提供才更新（非空覆盖） |

## 3. 安全与边界

| 项 | 标准 |
|----|------|
| 文件大小 | ≤ 20MB（超出 413）；行数不设硬上限（流式逐行解析） |
| 字符串截断 | handle ≤ 255、name ≤ 500、URL ≤ 1000（超长截断并记 warning 入报告） |
| 内容安全 | 不执行文件内任何 URL；`source_url` 仅入库展示，不做服务端抓取（无 SSRF 面） |
| 日志 | 导入动作记 audit_log（操作者、文件大小、report 摘要，复用 shared audit_service） |
| 限流 | 导入端点叠加 RATE_LIMIT 常规桶即可（管理员工具，无需特殊） |

## 4. 验收用例（导入服务测试清单）

1. 合法文件：series/contest/talent/result 全部正确落库，聚合正确
2. 重复导入同一文件：结果幂等（行数一致、无重复行）
3. 空文件 / 全无效行：**拒收且 DELETE 未发生**（守卫回归用例，对应 lab 事故）
4. 批内重复 handle：保留最后一条，无唯一键冲突
5. schema_version="2.0"：400 拒收
6. meta/contest 不一致：400 拒收
7. 二次导入同一场但榜单变化（源站重判）：旧 results 被替换而非叠加
8. 画像字段 null：不覆盖已有值；max_rating 只增不降
9. 团队赛文件（含 team 行）：team 落库、团队 result 关联 team_id、person.team_name 正确挂接
10. person.team_name 无对应 team 行：自动补建 team（仅 name）并记 warning，不拒收
11. 批内重复 team（同 name+school）：members 合并、result 保留最后一条
