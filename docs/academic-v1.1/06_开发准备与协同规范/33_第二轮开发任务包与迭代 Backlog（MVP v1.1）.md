# 33_第二轮开发任务包与迭代 Backlog（MVP v1.1）

**文档名称**：第二轮开发任务包与迭代 Backlog（MVP v1.1）  
**文档编号**：33  
**版本**：V1.0  
**状态**：冻结版  
**适用范围**：智能人才库—学术人才子系统 MVP v1.1

---

## 1. 文档目标

本文件用于将 v1.1 已冻结的需求和方案转换为可执行的开发任务包，以便：

- 做迭代排期
- 给 Claude Code 拆任务
- 组织前后端联调
- 明确先做什么、后做什么
- 为测试和验收准备建立映射

v1.1 不再适合用单一“大开发任务”推进，而应按模块化和链路化方式拆分，优先保证每个阶段都形成可演示、可联调、可回归的结果。

---

## 2. 开发总体原则

1. 以 `v1.0.0-mvp-baseline` 为稳定基线开展 v1.1 开发。  
2. 采用“先框架、后页面、再后台、最后联调收口”的顺序。  
3. 每个任务包尽量控制为一个页面、一个模块或一个接口族。  
4. 先完成双主视角主链路，再补充运营和后台能力。  
5. 每个任务包都必须关联到明确的文档依据、代码范围和验收口径。

## 4. 分任务包详细说明

### TP1 信息架构与导航升级
#### 目标
让 v1.1 的页面骨架和术语体系稳定下来，为后续前后端开发提供统一入口。

#### 主要任务
- 左侧导航调整为：首页、技术要素、国家院校、人才搜索、我的收藏、权限管理
- 全量替换“技术类目”为“技术要素”
- 新增默认视角配置逻辑
- 更新路由、菜单和文案

#### 依赖文档
- 31 / 32 / 06B / 13B / 23B

### TP2 首页主视角概要区
#### 目标
将首页改造为统一入口页，完成双主视角概要和热点跳转。

#### 主要任务
- 保留首页基础统计与搜索区
- 新增技术要素概要卡
- 新增国家院校概要卡
- 新增热门技术要素、重点国家、重点院校标签
- 带参跳转到技术要素页和国家院校页

### TP3 技术要素页面
#### 目标
形成业务部门可用的主分析页面。

#### 主要任务
- 技术要素页筛选区
- 概要统计
- 国家分布 Tab
- 院校分布 Tab
- 人才明细 Tab
- 与首页和详情页联通

### TP4 国家院校页面
#### 目标
形成平台部门可用的主分析页面。

#### 主要任务
- 区域/国家/学校筛选区
- 概要统计
- 院校分布 Tab
- 技术要素分布 Tab
- 人才明细 Tab
- 与首页、技术要素页和详情页联通

### TP5 搜索增强与详情增强
#### 目标
提升用户找人和判断人的效率。

#### 主要任务
- 搜索页新增技术要素、技术方向、区域、国家、学校、毕业状态、待确认状态等筛选
- 搜索排序、重置、分页优化
- 人才详情页新增技术标签、招聘判断摘要、完整度、待确认项

### TP6 收藏与人才池闭环
#### 目标
打通发现人才后的轻量运营闭环。

#### 主要任务
- 收藏 / 取消收藏
- 创建人才池
- 加入人才池
- 添加备注
- 更新跟进状态
- 我的收藏页承接结果

### TP7 权限扩展
#### 目标
完成多维资源权限扩展与统一注入。

#### 主要任务
- 学校范围权限
- 国家范围权限
- 技术要素范围权限
- 默认视角配置
- 首页统计、热点、列表、详情、导出统一受控

### TP8 采集配置与任务管理
#### 目标
形成后台可控采集基础能力。

#### 主要任务
- 采集范围配置页
- 采集策略配置页
- 手动触发任务
- 任务列表与状态展示

### TP9 版本发布与数据质量
#### 目标
形成“任务完成 ≠ 前台立刻生效”的可控发布机制。

#### 主要任务
- 候选数据版本列表
- 当前生效版本标记
- 手动发布
- 质量摘要展示
- 轻量纠偏

### TP10 联调测试与验收收口
#### 目标
完成全链路联调、缺陷收口、验收演示资料整理。
