## 1. 文档目标

本文件用于约束 v1.1 阶段“人 + AI（Claude Code）协同开发”的工作方式，重点解决：
- Claude Code 每次应该处理多大粒度的任务
- 进入代码前应该先读哪些文档
- 哪些分支可以改，哪些分支不能直接动
- 改动页面、接口、权限、状态时如何联动
- 每次完成后需要输出什么内容

---

## 2. 协同开发原则

1. **先文档、后代码**：Claude Code 修改前必须先读文档。  
2. **小步快跑**：一次只改一个页面、一个模块或一个接口族。  
3. **最小必要改动**：优先做增量增强，不做大面积无关重构。  
4. **主线稳定优先**：不得直接破坏 `main` 分支可演示性。  
5. **输出可审查**：每次修改后必须有变更摘要、影响范围、验证方式。  
6. **文档优先**：实现与文档冲突时，先指出冲突，不得直接偏离。

## 5. 任务拆分规范

### 5.1 推荐任务粒度
- 一个页面
- 一个模块
- 一个接口组
- 一个后台子模块
- 一个权限子能力

### 5.2 不推荐任务粒度
- 一次改完整个 v1.1
- 一次同时改导航、页面、接口、权限、数据库
- 一次跨多个无直接关系模块

### 5.3 任务示例
- 首页新增双概要卡
- 技术要素页实现国家分布 Tab
- 国家院校页实现技术要素分布 Tab
- 搜索页增加技术要素和国家筛选
- 收藏与人才池前后端联调
- 采集范围配置页开发
- 版本发布接口与页面联调

## 6. 任务输入模板

每次给 Claude Code 的输入建议至少包含：
1. 任务名称  
2. 目标模块/页面  
3. 文档依据  
4. 当前代码位置  
5. 改动范围限制  
6. 本次不允许做的事  
7. 完成后输出要求

---

## 7. 代码变更约束

### 7.1 页面改动
- 必须遵循 13B 和 26B
- 不得擅自新增未冻结字段
- 不得把首页做重
- 不得将热点模块做成复杂 BI 风格

### 7.2 接口改动
- 必须遵循 28B
- DTO 新增字段必须同步更新相关文档
- 统计和列表接口必须考虑权限边界

### 7.3 权限改动
- 必须遵循 14B
- 后端必须是最终权限边界
- 不得仅依赖前端隐藏按钮

### 7.4 状态改动
- 必须遵循 26B
- 不允许临时创造状态值
- 如需新增状态，先回文档层评审

### 7.5 数据模型改动
- 必须遵循 12B
- 不得将 OpenAlex 原始结构直接暴露给前台
- 不得绕过版本和发布机制直接覆盖线上结果

## 8. Claude Code 输出要求

每次任务完成后，Claude Code 必须输出：
- 变更摘要
- 涉及文件
- 影响范围
- 验证方式
- 风险与后续建议

---

## 9. commit 规范建议

### 9.1 前缀
- feat:
- fix:
- refactor:
- chore:
- docs:

### 9.2 示例
- `feat: add home overview cards for tech element and country school`
- `feat: implement tech element page country distribution`
- `fix: apply permission filtering on home overview stats`

---

## 10. 评审与回归要求

### 10.1 评审重点
- 是否符合文档冻结内容
- 是否超范围修改
- 是否引入权限漏洞
- 是否改变统计口径
- 是否破坏已有可演示链路

### 10.2 回归重点
涉及以下内容时必须补做回归：
- 首页摘要
- 搜索结果
- 权限逻辑
- 收藏状态
- 当前生效版本显示
- 技术要素和国家院校页联动逻辑

## 12. 结论

本文件作为 v1.1 阶段 Claude Code 协同开发的执行规范。  
在整个 v1.1 开发过程中，应优先保证文档一致性、任务粒度合理性和主线稳定性，避免 AI 协同开发带来失控式改动。
