# 10B_详细设计说明（学术人才子系统 MVP v1.1）

**文档编号**：10B  
**版本**：V1.0  
**状态**：冻结版  
**文档类型**：详细设计说明（长版源稿 / Markdown）

## 1. 文档概述

### 1.1 编制背景
学术人才子系统在 `v1.0.0-mvp-baseline` 阶段已完成基础可演示能力，包括首页总览、关键词搜索、按国家/学校浏览、学校信息页、人才列表页、人才详情页及基础权限控制。  
试用后，系统目标从“学校维度的学术人才浏览库”升级为“面向研发招聘的技术要素与国家院校双视角人才发现与轻量运营平台”。  
因此，`v1.1` 需要在页面、服务、状态、权限、数据版本与发布、异常处理等方面给出可实施级详细设计。

### 1.2 文档目标
本文件用于明确：
- 首页、技术要素、国家院校、搜索、详情、收藏、后台配置等页面的详细组成与交互方式
- 页面状态如何组织，尤其是筛选、分页、Tab 切换、局部刷新、跳转参数恢复
- 应用服务层如何拆分
- 统计与明细如何共享统一查询上下文
- 采集任务、候选版本、质量摘要、管理员发布、前台生效之间的链路
- 权限控制在页面层、接口层、数据层如何同时落地
- 异常处理、降级处理和实施约束

## 2. 设计原则

### 2.1 基线继承原则
所有 `v1.1` 实现都必须建立在 `v1.0.0-mvp-baseline` 基线之上。除非确有必要，不允许为了“代码更优雅”而进行大面积重构，应优先采用“增量增强”和“新增模块”的方式实现。

### 2.2 双主视角并行原则
`技术要素` 与 `国家院校` 是两个并行主视角：前者服务业务部门的技术方向分析心智，后者服务平台用户的区域/国家/学校分析心智。两个主视角共享同一人才底座，但页面组织方式、主筛选维度和主统计口径不同。

### 2.3 首页轻入口原则
首页承担统一入口、全局基础概览、双主视角摘要看板和快速跳转入口的职责，不是完整分析页，不能把技术要素页和国家院校页的完整分析内容回塞到首页。

### 2.4 权限统一口径原则
首页基础统计、技术要素摘要、国家院校摘要、热点标签、列表、详情、导出和后台操作都必须统一受权限控制。权限不一致是本系统最容易引发“看起来能用但实际不能用”的问题，因此必须把权限注入点和结果裁剪点前置并写清楚。

### 2.5 数据版本隔离原则
数据采集、数据构建、候选版本生成、管理员发布、前台生效必须是相互区分的步骤，不允许出现“任务成功后数据自动替换前台”的隐含逻辑。

## 3. 系统详细设计总览

### 3.1 分层结构
系统详细设计建议分为四层：

#### 页面与交互层
负责页面结构、布局区块、按钮、表单、列表、卡片、Tab 和跳转等用户直接可见内容。

#### 页面编排与状态层
负责页面状态管理，例如当前筛选条件、当前 Tab、分页与排序状态、局部 loading / error / empty、路由参数恢复、局部操作后的页面刷新策略。

#### 应用服务层
主要包括：首页摘要服务、技术要素分析服务、国家院校分析服务、搜索服务、人才详情服务、收藏与人才池服务、权限服务、采集配置与任务服务、数据版本与发布服务、数据质量与纠偏服务。

#### 数据处理与存储层
负责源数据接入、学校归一、角色识别、技术方向映射、聚合统计、当前生效版本切换、审计和纠偏记录保存。

### 3.2 系统主链路
- 人才发现链路：首页 / 技术要素 / 国家院校 / 搜索 → 人才明细 → 人才详情
- 轻量运营链路：搜索结果 / 列表结果 / 详情页 → 收藏 / 人才池 / 备注 / 跟进状态 → 我的收藏
- 数据运营链路：采集范围配置 / 采集策略配置 → 采集任务 → 候选版本 → 质量摘要 / 纠偏 → 发布 → 前台生效

## 4. 前台页面详细设计

### 4.1 首页详细设计
首页承担以下职责：
- 展示全局基础统计
- 展示当前数据版本和更新时间
- 提供关键词搜索入口
- 提供技术要素和国家院校两个主视角的概要统计
- 提供热门技术要素、重点国家和重点院校的快捷跳转入口

页面布局建议分为：标题与说明区、基础统计区、搜索区、主视角概要区、辅助提示区。  
首页建议分三个摘要接口获取数据：`首页全局基础统计`、`首页技术要素概要`、`首页国家院校概要`。  
首页页面状态需支持：`loading`、`normal`、`partial_empty`、`empty`、`error`。  
热点标签不由前端自行计算，必须由后端返回；概要统计必须基于当前用户权限范围；首页不展示复杂图表。

### 4.2 技术要素页面详细设计
技术要素页面是面向业务部门的主分析页面，承担以下职责：
- 从技术要素 / 技术方向角度展示当前人才规模
- 展示该方向下的人才国家分布、院校分布和人才明细
- 支持快速跳转到详情和运营动作

页面布局建议为：页面标题与当前筛选上下文、筛选区、概要统计区、Tabs 主视图区。  
筛选字段建议包括：技术要素、技术方向、关键词、国家、学校、人才角色、是否已毕业、待确认状态、查询按钮、重置按钮。  
Tabs 包括：国家分布、院校分布、人才明细。  
国家分布点击某个国家，可切换到“当前技术要素 + 当前国家”的结果上下文，也可跳转到国家院校页并带入当前国家和技术要素条件。  
院校分布点击某个院校，可进入“当前技术要素 + 当前院校”的人才结果。  
人才明细中，教授偏卡片、学生偏表格，支持收藏、加入人才池和查看详情。  
页面需维护 `filterState`、`summaryLoading`、`activeTab`、`tabListLoading`、`paginationState`、`jumpContext` 等状态。  
概要统计与列表必须共享同一筛选条件和同一 Query Context。

### 4.3 国家院校页面详细设计
国家院校页面是面向平台侧的主分析页面，承担以下职责：
- 从区域 / 国家 / 学校角度展示人才供给
- 展示当前范围内的重点院校和主要技术要素分布
- 展示当前范围下的人才明细
- 与技术要素页形成交叉下钻能力

页面布局建议为：页面标题与当前上下文、筛选区、概要统计区、Tabs 主视图区。  
筛选字段建议包括：区域、国家、学校、技术要素、技术方向、关键词、人才角色、查询、重置。  
Tabs 包括：院校分布、技术要素分布、人才明细。  
国家院校页中的技术要素是辅助维度，不应反向抢占页面主轴。  
区、国、校联动必须清晰，不允许页面退化为“只是另一个搜索页”。

### 4.4 搜索页面详细设计
搜索页是统一结果页，而不是任一视角的专属页面。  
筛选区字段包括：关键词、技术要素、技术方向、区域、国家、学校、人才角色、是否已毕业、待确认状态。  
结果区支持：总结果数、排序、分页、卡片/表格视图提示、收藏 / 入池 / 查看详情。  
搜索页的结果 DTO 必须与技术要素页和国家院校页复用，不单独定义另一套人才口径。

### 4.5 人才详情与轻量运营
详情页从静态信息展示页升级为招聘判断页，除基础信息外，还要增加：技术要素 / 技术方向、主方向 / 次方向、招聘判断摘要、代表成果摘要、数据完整度、待确认项。  
运营动作包括：收藏、加入人才池、添加备注、设置跟进状态。

## 5. 页面状态管理详细设计

### 5.1 设计目标
`v1.1` 页面比 `v1.0` 更复杂，需要统一页面状态设计，避免筛选后概要统计和列表不同步、切换 Tab 后筛选条件丢失、从首页跳转后筛选未正确恢复、局部操作导致全页刷新等问题。

### 5.2 通用页面状态模型
建议为分析型页面统一维护：
- `queryContext`：页面业务筛选条件、当前路由来源参数、当前数据版本、排序和分页参数
- `uiState`：当前 Tab、视图模式、弹窗状态
- `dataState`：概要统计 loading / success / error，列表 loading / success / error，empty 状态，pagination 状态
- `operationState`：收藏中、保存备注中、状态更新中、发布中、任务触发中

### 5.3 页面恢复要求
- 切换 Tab 不丢失当前筛选
- 浏览器返回时尽量恢复上一次查询
- 首页热点标签跳转时要能正确恢复 `jumpContext`
- URL 中已有关键条件时应优先恢复

## 6. 服务层详细设计

### 6.1 首页摘要服务
负责生成：首页基础统计、技术要素概要、国家院校概要、热点标签。  
输入：当前用户、当前生效数据版本、当前用户权限范围。  
处理逻辑：
1. 获取当前 current live version
2. 基于权限获取可见人才集合
3. 统计基础卡片指标
4. 统计技术要素概要
5. 统计国家院校概要
6. 基于排序规则生成热门技术要素和重点国家院校
7. 组装 DTO 和 jumpParams

### 6.2 技术要素分析服务
负责技术要素页的筛选、概要统计、国家分布、院校分布和人才明细。  
输入：TechElementQueryDTO、当前用户权限、当前版本信息。  
核心处理步骤：
1. 解析筛选条件
2. 构建 Query Context
3. 注入权限边界
4. 注入当前版本边界
5. 获取人才基础集合
6. 在集合上生成概要统计
7. 在集合上聚合国家分布
8. 在集合上聚合院校分布
9. 在集合上分页生成人才明细

### 6.3 国家院校分析服务
负责国家院校页的筛选、概要统计、院校分布、技术要素分布和人才明细。  
主轴从技术要素转为区域 / 国家 / 学校，技术要素只作为辅助筛选和结果分析维度存在。

### 6.4 搜索服务
统一处理跨视角复杂检索需求：
1. 解析筛选条件
2. 注入权限边界
3. 限定当前生效版本
4. 执行关键词匹配和多维筛选
5. 执行排序和分页
6. 组装人才列表 DTO

### 6.5 人才详情服务
负责组装单人才详情页数据，包括：基础信息、技术标签、学术摘要、招聘判断摘要、代表成果、当前收藏与跟进状态。  
处理步骤：
1. 校验当前用户是否有权查看该人才
2. 拉取人才基础信息
3. 拉取当前有效技术标签
4. 拉取代表成果摘要
5. 拉取收藏状态、跟进状态、备注概要
6. 组装 TalentDetailDTO

### 6.6 收藏与人才池服务
负责：收藏创建/取消、人才池创建与加人、备注保存、跟进状态更新。  
关键逻辑：
- 创建收藏幂等
- 取消收藏建议采用状态更新，不物理删除
- 人才池成员加入需校验对象仍可见
- 跟进状态更新需留痕

### 6.7 权限服务
负责向其他服务提供统一权限边界，包括：用户角色、页面可见性、学校范围、国家范围、技术要素范围、默认视角。  
权限服务不直接负责业务查询，但必须在所有业务服务构造 Query Context 时注入这些边界。

### 6.8 采集配置与任务服务
- 采集范围配置服务：维护国家、学校、技术要素、技术方向四类范围项
- 采集策略服务：维护周期、模式、重试、批量、限流、超时等参数
- 任务执行服务：手动触发任务、自动调度任务、记录任务生命周期状态、输出执行摘要

### 6.9 数据版本与发布服务
负责生成候选数据版本、管理当前生效版本、执行发布与回滚、对前台暴露当前版本信息。  
关键逻辑：
- 任一时点只能有一个当前生效版本
- 未发布版本不得被前台读取
- 回滚动作需有明确日志

### 6.10 数据质量与纠偏服务
负责汇总质量摘要、管理待确认项、执行轻量人工修正并保留修正前后记录。  
轻量纠偏包括：修正技术方向、修正角色、标记待确认、标记排除展示。

## 7. 统一查询上下文设计

### 7.1 设计目标
防止页面之间和页面内区块之间查询口径漂移。

### 7.2 建议结构
一个统一 Query Context 至少包含：
- `businessFilters`
- `permissionFilters`
- `versionFilter`
- `displayFilters`
- `queryMeta`

### 7.3 应用场景
- 首页热点标签可视为 Query Context 快照
- 技术要素页和国家院校页的所有子接口必须共享 Query Context
- 搜索页结果接口也应复用同一上下文设计思路

## 8. 统计与热点标签生成设计

### 8.1 统计生成前提
所有统计必须满足：
1. 当前生效版本  
2. 当前用户权限范围  
3. 当前页面业务筛选条件  

### 8.2 热门技术要素规则
建议：
1. 按人才数降序  
2. 再按覆盖院校数降序  
3. 取 Top N

### 8.3 重点国家和重点院校规则
建议：
- 国家：按人才数
- 学校：按人才数

## 9. 权限注入与结果裁剪详细设计

### 9.1 权限作用点
- 首页统计
- 热点标签
- 技术要素页
- 国家院校页
- 搜索页
- 详情页
- 导出
- 后台管理操作

### 9.2 裁剪原则
- 权限应在查询之前注入
- 不允许先查全量再前端隐藏
- 不允许统计口径与列表口径不一致

## 10. 采集、版本与发布详细流程

### 10.1 主流程
1. 配置范围与策略  
2. 创建任务  
3. 执行采集与构建  
4. 生成候选版本  
5. 生成质量摘要  
6. 管理员发布  
7. 前台切换 current live version  

### 10.2 回滚流程
1. 发现问题  
2. 管理员选择历史版本  
3. 执行回滚  
4. 写 publish_record  
5. 前台切换  

## 11. 数据质量与轻量纠偏详细处理逻辑

### 11.1 待确认对象设计
对于学校、角色、技术标签等无法高置信度确定的信息，应明确为 `pending_confirm`，而不是以正式信息展示。

### 11.2 纠偏生效策略
建议优先遵循版本管理逻辑，不直接无痕覆盖线上已发布结果。

## 12. 异常处理与降级设计

### 12.1 页面异常
- 局部失败不阻断整页
- 空态和错误态区分明确
- 允许重试

### 12.2 权限异常
- 403 页面级
- 404/无权限 对象级
- 安全返回，不泄露对象存在性

### 12.3 任务异常
- 单条失败不阻断整批
- 失败记录摘要
- 不影响 current live version

### 12.4 发布异常
- 失败不切版本
- 原版本继续服务
- 明确日志和提示

## 13. 开发与联调约束

1. 页面实现必须遵循 `13B + 26B`
2. DTO 与字段必须遵循 `28B`
3. 权限实现必须遵循 `14B`
4. 数据对象与状态必须遵循 `12B`
5. 每次 Claude Code 任务只允许处理一个页面 / 模块 / 接口族
6. 不允许在 `main` 分支直接进行高风险修改

## 14. 文档结论

本文件将学术人才子系统 `MVP v1.1` 从总体方案层进一步下沉到详细设计层。通过页面设计、状态设计、服务拆分、统一查询上下文、权限裁剪、采集与版本发布链路、数据质量与轻量纠偏等内容的详细展开，系统已经具备进入分模块开发、前后端联调和测试验收的清晰设计基础。后续若需变更主流程、状态集、权限边界或版本链路，必须先在文档层完成评审，再进入代码实现。
