# v1.4 智能推荐与 JD 匹配版本规划

## 版本概述

| 项目 | 内容 |
|------|------|
| **当前版本** | v1.3.2 (学术人才子系统 MVP) |
| **目标版本** | v1.4 |
| **版本定位** | 智能推荐与 JD 匹配版本 |
| **预计工期** | 9 周 / 49 人天 |

### 核心需求

| 需求 | 描述 | 技术复杂度 |
|------|------|-----------|
| **智能推荐** | 根据候选人画像推荐相似人才 | 中 - 向量相似度 |
| **加强搜索** | 全文搜索、多字段搜索、模糊匹配 | 低 - PostgreSQL 原生支持 |
| **JD 匹配** | 输入岗位 JD，智能匹配候选人 | 高 - LLM + 向量匹配 |

### 关键约束

1. **搜索引擎分级**：基础搜索不调用 LLM，控制成本
2. **LLM 功能可选**：用户勾选启用，支持自定义 API 地址

### 现状分析

| 方面 | 现状 | 目标 |
|------|------|------|
| 搜索能力 | 仅 `ILIKE` 模糊匹配 | 全文索引 + 语义搜索 |
| 向量嵌入 | 无 | pgvector 支持 |
| LLM 集成 | 无 | 可选的 LLM 网关 |
| 推荐算法 | 规则评分（CS 背景、角色置信度） | 向量相似度 + 规则 |

### 模块职责与依赖关系

| 模块 | 职责 | 依赖 | LLM调用 | 状态 |
|------|------|------|---------|------|
| **SearchService** | 关键词/全文/语义搜索 | Repository | ❌ 不调用 | 独立 |
| **RecommendService** | 相似人才推荐 | EmbedService | ❌ 不调用 | 弱依赖 |
| **JDMatchService** | JD解析与匹配 | LLMGateway + EmbedService | ✅ 按需 | 强依赖 |
| **EmbedService** | 向量嵌入生成 | LLMGateway | ✅ 批量 | 中依赖 |
| **LLMGateway** | LLM API 封装 | OpenAI SDK | ✅ 核心 | 基础设施 |
| **CacheManager** | 多级缓存 | Redis (可选) | ❌ 不调用 | 基础设施 |

### 技术选型

| 需求 | 方案 | 理由 |
|------|------|------|
| 全文搜索 | PostgreSQL tsvector + GIN 索引 | 零运维，与现有架构集成 |
| 向量嵌入 | PostgreSQL pgvector 扩展 | 无需新数据库 |
| JD 解析 | DeepSeek API | 国产模型，性价比高 |
| 推荐算法 | 规则 + 向量相似度 | MVP 平衡效果与成本 |
| 缓存 | Redis (可选) | 复用现有基础设施 |

```sql
-- 启用 pg_trgm 扩展
CREATE EXTENSION IF NOT EXISTS pg_trgm;

-- 添加全文搜索向量列
ALTER TABLE search_talent_document
ADD COLUMN search_vector tsvector;

-- 创建 GIN 索引
CREATE INDEX ix_search_talent_document_vector
ON search_talent_document USING GIN(search_vector);

-- 创建更新触发器
CREATE OR REPLACE FUNCTION update_search_vector()
RETURNS TRIGGER AS $$
BEGIN
    NEW.search_vector :=
        setweight(to_tsvector('simple', COALESCE(NEW.name, '')), 'A') ||
        setweight(to_tsvector('simple', COALESCE(NEW.title, '')), 'B') ||
        setweight(to_tsvector('simple', COALESCE(NEW.research_interests, '')), 'C') ||
        setweight(to_tsvector('simple', COALESCE(NEW.school_name, '')), 'D');
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

## 架构改进设计

### 1. 接口抽象设计

**问题**：缺少接口抽象，不便于 Mock 测试和替换实现。

**解决方案**：定义 Protocol 接口，实现依赖倒置。

```python
# services/llm/protocols.py
from typing import Protocol, List
from dataclasses import dataclass

@dataclass
class JDFeatures:
    """JD 解析结果"""
    skills: List[str]
    experience: str
    research_areas: List[str]
    role_type: str
    education_level: str | None

@dataclass
class EmbeddingResult:
    """嵌入生成结果"""
    embedding: List[float]
    model: str
    tokens_used: int

class LLMGatewayProtocol(Protocol):
    """LLM 网关抽象接口 - 便于 Mock 和替换实现"""

    async def parse_jd(self, jd_text: str) -> JDFeatures: ...
    async def generate_embedding(self, text: str) -> EmbeddingResult: ...
    async def generate_embedding_batch(self, texts: List[str]) -> List[EmbeddingResult]: ...
    async def health_check(self) -> bool: ...
```
