# 生产环境部署指南

本文档描述智能人才库系统的生产环境部署步骤。

## 系统要求

### 硬件要求
- CPU: 2核及以上
- 内存: 4GB 及以上
- 存储: 20GB 及以上

### 软件要求
- Python 3.11+
- Node.js 20+
- PostgreSQL 14+
- Nginx (推荐用于反向代理)

## 环境变量配置

### 后端环境变量

创建 `backend/.env` 文件：

```env
# Application
APP_NAME=智能人才库 API
APP_VERSION=1.2.0
DEBUG=false
ENVIRONMENT=production

# Database
DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/talent_db
DATABASE_SYNC_URL=postgresql://user:password@localhost:5432/talent_db

# JWT
SECRET_KEY=your-very-secure-secret-key-change-in-production
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_HOURS=8

# CORS
CORS_ORIGINS=["https://your-domain.com"]

# Rate Limiting
RATE_LIMIT_ENABLED=true
RATE_LIMIT_PER_MINUTE=100

# OpenAlex
OPENALEX_BASE_URL=https://api.openalex.org
OPENALEX_EMAIL=your-email@example.com
OPENALEX_RATE_LIMIT=10
```

### 前端环境变量

创建 `frontend/.env` 文件：

```env
VITE_API_BASE_URL=https://your-domain.com/api/v1
```

## 部署步骤

### 1. 数据库准备

```bash
# 创建数据库
sudo -u postgres psql -c "CREATE DATABASE talent_db;"

# 创建用户
sudo -u postgres psql -c "CREATE USER talent_user WITH PASSWORD 'secure_password';"
sudo -u postgres psql -c "GRANT ALL PRIVILEGES ON DATABASE talent_db TO talent_user;"

# 运行迁移
cd backend
alembic upgrade head
```

### 2. 后端部署

```bash
# 安装依赖
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 启动服务 (使用 gunicorn)
gunicorn app.main:app \
  --workers 4 \
  --worker-class uvicorn.workers.UvicornWorker \
  --bind 0.0.0.0:8003 \
  --access-logfile - \
  --error-logfile -
```

### 3. 前端部署

```bash
# 安装依赖
cd frontend
npm install

# 构建生产版本
npm run build

# 部署静态文件到 Nginx
sudo cp -r dist/* /var/www/talent-platform/
```

### 4. Nginx 配置

创建 `/etc/nginx/sites-available/talent-platform`:

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态文件
    location / {
        root /var/www/talent-platform;
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8003;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 健康检查
    location /health {
        proxy_pass http://127.0.0.1:8003/health;
    }
}
```

### 5. 启用 HTTPS (推荐)

```bash
# 安装 Certbot
sudo apt install certbot python3-certbot-nginx

# 获取证书
sudo certbot --nginx -d your-domain.com

# 自动续期
sudo certbot renew --dry-run
```

## 使用 Docker Compose 部署

创建 `docker-compose.prod.yml`:

```yaml
version: '3.8'

services:
  postgres:
    image: postgres:14
    environment:
      POSTGRES_DB: talent_db
      POSTGRES_USER: talent_user
      POSTGRES_PASSWORD: secure_password
    volumes:
      - postgres_data:/var/lib/postgresql/data
    restart: always

  backend:
    build: ./backend
    environment:
      - DATABASE_URL=postgresql+asyncpg://talent_user:secure_password@postgres:5432/talent_db
      - ENVIRONMENT=production
    depends_on:
      - postgres
    restart: always

  frontend:
    build: ./frontend
    depends_on:
      - backend
    restart: always

  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
    depends_on:
      - frontend
      - backend
    restart: always

volumes:
  postgres_data:
```

启动服务：

```bash
docker-compose -f docker-compose.prod.yml up -d
```

## 监控与日志

### 日志格式

后端使用 JSON 结构化日志，包含以下字段：
- `asctime`: 时间戳
- `levelname`: 日志级别
- `name`: 日志器名称
- `message`: 日志消息
- `request_id`: 请求追踪 ID

### 请求追踪

每个请求包含唯一的 `X-Request-ID` 响应头，可用于追踪请求链路。

### 限流

- 默认限流: 100 请求/分钟
- 响应头:
  - `X-RateLimit-Limit`: 限流阈值
  - `X-RateLimit-Remaining`: 剩余请求数
  - `Retry-After`: 触发限流后的重试等待时间

## 故障排查

### 常见问题

1. **数据库连接失败**
   - 检查 PostgreSQL 服务状态
   - 验证连接字符串和凭据
   - 确认防火墙规则

2. **API 返回 429 Too Many Requests**
   - 检查限流配置
   - 确认客户端请求频率

3. **前端页面空白**
   - 检查构建输出
   - 验证 API 基础 URL 配置
   - 查看浏览器控制台错误

### 健康检查

```bash
# 检查后端健康状态
curl http://localhost:8003/health

# 检查数据库连接
curl http://localhost:8003/api/v1/health
```

## 备份策略

### 数据库备份

```bash
# 手动备份
pg_dump -U talent_user talent_db > backup_$(date +%Y%m%d).sql

# 自动备份 (cron)
0 2 * * * pg_dump -U talent_user talent_db > /backups/talent_db_$(date +\%Y\%m\%d).sql
```

### 恢复数据库

```bash
psql -U talent_user talent_db < backup_20260101.sql
```

## 安全建议

1. 定期更新依赖包
2. 使用强密码和密钥
3. 启用 HTTPS
4. 配置防火墙规则
5. 定期备份数据
6. 启用审计日志
7. 监控异常请求
